7. 消息协议与加密 · ECDH + AES-GCM + SessionToken

✔ 已确认 · C2 拓扑

7.1 传输层：Length(4B) + MsgID(4B) + SessionId(4B) + Body

与 C2 拓扑适配——增加了 4 字节 SessionId 让 GateServer 零解密路由。 SessionId 由 GateServer 在 TCP 连接建立时分配，客户端在所有后续消息中携带。 

#pragma pack(push, 1)
struct PacketHeader {
    uint32_t length;     // 整包长度(含头)，大端。不含 encryption overhead
    uint32_t msgId;      // EMsgId 枚举值，大端
    uint32_t sessionId;  // Gate 分配的会话 ID（明文——Gate 路由用）
    // 紧接着: Body (可能是明文 or AES-GCM 密文)
};
#pragma pack(pop)

7.2 消息 ID 枚举（msg_id.proto）

enum EMsgId {
    MSG_HEARTBEAT_REQ=1;       MSG_HEARTBEAT_RSP=2;

    // 登录——走 LoginServer（TLS）
    MSG_LOGIN_AUTH_REQ=100;    MSG_LOGIN_AUTH_RSP=101;

7.4 加密：ECDH 密钥协商 + AES-256-GCM

加密逻辑在 WorldServer 侧（Gate 不持有 SessionKey，纯透传）。 LoginServer 做 ECDH 协商生成 SessionKey → 封装进 SessionToken → WorldServer 解密还原 → WorldServer 用 SessionKey 做 AES-GCM 对业务消息 Body 加解密。 

// CryptoSession — WorldServer 侧（每 sessionId 一个）
struct CryptoSession {
    std::vector<uint8_t> sessionKey;     // 32 字节 AES-256 密钥（从 SessionToken 还原）
    uint32_t  lastSequence = 0;             // 已收到的最大序列号（带内序列号，非 TCP seq）
    uint32_t  sequenceBase  = 0;             // 序列号回绕时的 base 偏移
    uint64_t  clientRandom = 0;              // 客户端生成的随机前缀（nonce 下半部分）
};

// 加密 → 发送
std::vector<uint8_t> EncryptOutbound(const CryptoSession& cs, const std::vector<uint8_t>& plaintext) {
    // nonce = sequence(4B) + clientRandom(8B) = 12 字节
    auto seq = cs.lastSequence + 1;  // 每个方向独立序列号
    // 返回: ciphertext + GCM tag
    return Aes256GcmEncrypt(cs.sessionKey, BuildNonce(seq, cs.clientRandom), plaintext);
}

// 解密 → 入站处理
std::optional<std::vector<uint8_t>> DecryptInbound(CryptoSession& cs, const std::vector<uint8_t>& ciphertext, uint32_t seq) {
    if (!cs.ValidateSequence(seq)) return std::nullopt;  // 防重放
    return Aes256GcmDecrypt(cs.sessionKey, BuildNonce(seq, cs.clientRandom), ciphertext);
}

7.5 加密边界总结

连接加密持有会话密钥的一方
Client ↔ LoginServerTLS——
Client → LoginServer (Auth Body)TLS 内明文——
LoginServer → Client (SessionToken)TLS 内明文——但 SessionToken 自带 HMAC 签名LoginServer 持有 LSS
Client ↔ GateServer (TCP)明文（SessionId + MsgID 明文，Body 密文）Gate 无密钥
Client ↔ WorldServer (逻辑层)AES-256-GCM(SessionKey, Body)WorldServer 持有 SessionKey
Gate ↔ WorldServer (内部 TCP)明文——内网可信——
WorldServer ↔ Center/Social/DB内网明文 or 内网 TLS（可配）——
⚠ 关键安全约束： WorldServer 只监听内网 IP（127.0.0.1 / 10.x / 172.16.x），不接受任何公网连接。
如果攻击者获取了 WorldServer 的内网 IP 并直接连接——包在防火墙层被丢弃（物理网络隔离）。
所有公网流量强制经过 GateServer。
