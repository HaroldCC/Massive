7b. SessionToken · 无状态 Gate 路由机制

1. 设计目标

C2 拓扑中，GateServer 必须完全无状态——不持有 SessionKey、不做加解密、不查数据库。 只做一件事：根据 SessionToken 的前几个字节（明文）做 O(1) 路由。 所有安全验证和加解密都由 WorldServer 完成。GateServer 宕机重启后， 客户端重新连接任意 Gate，Gate 无需任何恢复逻辑。

核心原则：SessionToken 是一个自包含的、防篡改的凭证。
LoginServer 签发 → 客户端持有 → 每次通信携带 → Gate 只读路由字段 → WorldServer 验证 HMAC 并还原 SessionKey。

Token 有效期策略：采用长有效期（8 小时），覆盖单次游玩。 不使用滑动窗口续期——一旦过期，客户端需重新走 LoginServer 完整 ECDH 流程获取新 Token。 这比复杂的 Token 续期协议更简单、更安全。

2. SessionToken 结构（46 字节）

// SessionToken — 46 字节自包含凭证
//
// [worldServerId: 2B] [accountId: 4B] [expireTime: 4B] [encryptedSessionKey: 32B] [HMAC-SHA256: 4B(truncated)]
//       ↑─── 明文段（10 字节，受 HMAC 保护）───↑   ↑─── 加密段（32 字节）───↑   ↑─ HMAC ─↑
//
// 明文段：GateServer 读取 worldServerId 做路由——O(1) 查表，无需解密。
//         accountId 和 expireTime 明文传输但受 HMAC 保护——客户端无法篡改。
//
// 加密段：AES-256-ECB(LSS_key, sessionKey) = 32B 密文。
//         sessionKey 长度 32B → AES-256-ECB 输出的密文也是 32B——天然对齐，无截断、无 padding。
//         不用 GCM——HMAC 已覆盖整个 token 提供完整性保护，不需要 AEAD。
//
// HMAC: HMAC-SHA256(LSS_key, token[0..41])，截取前 4 字节。
//        覆盖整个 token 的明文段 + 加密段——任何篡改都会被检测。

struct SessionToken {
    static constexpr size_t kTotalSize  = 46;
    static constexpr size_t kPlainSize  = 10;   // 明文段: worldServerId(2B) + accountId(4B) + expireTime(4B)
    static constexpr size_t kKeyEncSize = 32;   // 加密的 SessionKey (AES-256-ECB, 32B→32B 无 padding)
    static constexpr size_t kHmacSize   = 4;    // HMAC-SHA256 截断

    uint8_t data[kTotalSize];

    // GateServer 只读这个——零解密
    uint16_t WorldServerId() const {
        uint16_t id;
        std::memcpy(&id, data, 2);
        return id;
    }
};

4. SessionToken 生命周期

Client → LoginServer: auth + ECDH
  │
  │ LoginServer:
  │   · argon2id 验证密码
  │   · ECDH → SessionKey
  │   · 选择 WorldServer（最少负载）
  │   · 构造 SessionToken（expireTime = now + 8h）
  │   · AES-256-ECB(LSS, sessionKey) → 32B 密文
  │   · HMAC-SHA256(LSS, token[0..41]) → 取前 4B
  │
  │ LoginServer → Client: {gateIPs: [...], sessionToken: <46 bytes>}
  │
Client → GateServer: TCP connect
  │ 首包: MSG_LOGIN_ENTER_WORLD_REQ { sessionToken: <46 bytes>, nonce: 8B }
  │
  │ Gate: 读 token[0..1] → worldServerId
  │       _sessionRoutes[sessionId] = {worldId, clientSocket}
  │       _worldConns[worldId] → 转发整包
  │
  │ WorldServer 收包:
  │   1. NonceVerifier.CheckAndInsert(pkt.nonce) —— 防重放
  │   2. HMAC-SHA256(LSS, token[0..41]) == token[42..45]?
  │   3. AES-256-ECB 解密 token[10..41] → SessionKey(32B)
  │   4. accountId + expireTime 从明文段读取并验过期
  │   5. 加载/创建 Entity → 绑定 sessionId → 绑定 CryptoSession{SessionKey}
  │
  │ WorldServer → Gate → Client: MSG_LOGIN_ENTER_WORLD_RSP

Token 过期（8 小时后）：
  客户端需要重新 TCP connect LoginServer（TLS）
  → 完整 ECDH → 新 SessionToken → 重新进入世界

5. LoginServer 签发逻辑

// LoginServer.cpp — SessionToken 签发
SessionToken IssueSessionToken(uint32_t accountId,
                              const std::vector<uint8_t>& sessionKey)
{
    auto worldServer = PickWorldServer();  // 最少负载选择
    auto expireTime  = time(nullptr) + 28800;  // 8 小时过期（覆盖单次游玩）

    SessionToken token;

    // 1. 明文段：worldServerId(2B) + accountId(4B) + expireTime(4B) = 10B
    uint8_t plaintext[10];
    std::memcpy(plaintext,      &worldServer.serverId, 2);
    std::memcpy(plaintext + 2, &accountId,             4);
    std::memcpy(plaintext + 6, &expireTime,            4);
    std::memcpy(token.data, plaintext, 10);

    // 2. 加密段：AES-256-ECB(<lssKey>, sessionKey) → 32B 密文（与明文同长，无 padding）
    auto encrypted = Aes256EcbEncrypt(_lssKey, sessionKey.data(), 32);
    if (encrypted.size() != 32) return {};
    std::memcpy(token.data + 10, encrypted.data(), 32);

    // 3. HMAC = HMAC-SHA256(LSS, token[0..41])，截取前 4 字节 → token[42..45]
    auto hmac = HmacSha256(_lssKey, token.data, 42);
    std::memcpy(token.data + 42, hmac.data(), 4);

    return token;
}

6. WorldServer 验证逻辑

// WorldServer.cpp — SessionToken 验证 + SessionKey 还原
struct TokenPayload {
    uint32_t accountId;
    uint32_t expireTime;
    std::vector<uint8_t> sessionKey;  // 32B
};

std::optional<TokenPayload> VerifySessionToken(const SessionToken& token) {
    // 1. 验 HMAC
    auto expectedHmac = HmacSha256(_lssKey, token.data, 42);
    if (std::memcmp(expectedHmac.data(), token.data + 42, 4) != 0)
        return std::nullopt;

    // 2. 解密 SessionKey: AES-256-ECB 解密 token[10..41] → 32B SessionKey
    auto decrypted = Aes256EcbDecrypt(_lssKey, token.data + 10, 32);
    if (!decrypted) return std::nullopt;

    TokenPayload payload;
    payload.sessionKey.assign(decrypted->begin(), decrypted->end());

    // 3. 从明文段提取 accountId + expireTime
    std::memcpy(&payload.accountId,  token.data + 2, 4);
    std::memcpy(&payload.expireTime, token.data + 6, 4);

    // 4. 过期检查（8 小时）
    if (payload.expireTime < time(nullptr))
        return std::nullopt;

    return payload;
}

7. GateServer 内部数据结构

// GateServer.h — 极简状态（连接级，非业务级）
class GateServer {
public:
    struct SessionRoute {
        uint16_t worldServerId;
        TcpSocketPtr clientSocket;
    };

    std::unordered_map<uint32_t, SessionRoute> _sessionRoutes;  // sessionId → Route
    std::unordered_map<uint16_t, TcpSocketPtr> _worldConns;     // worldId → TCP

    // 入站：客户端 → Gate → WorldServer
    void OnClientPacket(TcpSocketPtr clientSock, const std::vector<char>& data) {
        auto sessionId = ExtractSessionId(data);
        auto it = _sessionRoutes.find(sessionId);

        if (it == _sessionRoutes.end()) {
            if (auto token = TryExtractSessionToken(data)) {
                auto worldId = token->WorldServerId();
                _sessionRoutes[sessionId] = SessionRoute{worldId, clientSock};
                EnsureWorldConnection(worldId);
                ForwardToWorld(worldId, data);
            }
            return;
        }

        // 后续包——查缓存的 worldId 直接转发，零解析
        ForwardToWorld(it->second.worldServerId, data);
    }

    // 出站：WorldServer → Gate → Client
    void OnWorldOutbound(const std::vector<char>& data) {
        auto sessionId = ExtractSessionId(data);
        auto it = _sessionRoutes.find(sessionId);
        if (it != _sessionRoutes.end())
            SendToClient(it->second.clientSocket, data);
    }
};

8. 线格式 (Wire Format)

包类型结构加密
首包（登录进世界） [4B Length][4B MsgID=MSG_LOGIN_ENTER_WORLD_REQ][4B SessionId][8B Nonce][46B SessionToken 明文] 未加密——Gate 需读 SessionToken；Nonce 用于防重放
后续业务包 [4B Length][4B MsgID][4B SessionId][8B Nonce][AES-256-GCM Encrypted Body] Body 用 SessionKey(AES-256-GCM) 加密；Nonce 每次随机

9. 安全分析

攻击面防御
客户端篡改 SessionToken 明文段（worldServerId / accountId / expireTime）HMAC 覆盖明文段 + 加密段——WorldServer 验签失败 → 拒绝连接
客户端重放旧 SessionTokenNonce 校验（Bloom filter）+ expireTime 双重防护
客户端伪造 SessionToken伪造的 sessionKey 密文解密后不是合法密钥——WorldServer 拒绝
客户端直接连 WorldServer（绕过 Gate）WorldServer 只监听内网 IP，不接受公网连接
GateServer 被攻陷 → 读 BodyBody 是 AES-256-GCM 密文——Gate 没有 SessionKey
中间人攻击（LoginServer 响应被篡改）LoginServer 使用 TLS

10. 防重放：Nonce + Bloom Filter

每次客户端发起新连接（及关键业务包）携带 64-bit 随机 nonce。 WorldServer 用 Bloom filter 记录所有已验证的 nonce，拒绝已出现的 nonce。 不使用 seq_num——Gate 切换后 seq 必须重置，语义混乱。纯随机 nonce 更简洁。 

// WorldServer.cpp — Nonce 验证（Bloom filter, 128KB）
class NonceVerifier {
    static constexpr size_t kFilterBits = 1 << 20;  // 1M bits = 128KB
    static constexpr size_t kHashFuncs  = 3;

    std::bitset<kFilterBits> _filter;
    std::deque<std::pair<Clock::time_point, uint64_t>> _recent;

public:
    bool CheckAndInsert(uint64_t nonce) {
        if (ProbablySeen(nonce))
            return false;  // 可能已使用——拒绝（误判率 ~1%）
        Insert(nonce);
        _recent.push_back({Clock::now(), nonce});
        EvictOld(std::chrono::hours(8));  // 清理超过 Token 有效期的 nonce
        return true;
    }
};
Nonce 方案设计要点： Bloom filter 128KB 内存可支撑数百万 nonce，~1% 误判率（把未用过的 nonce 误判为已用过）。 1% 的合法请求被误拒可通过客户端自动重试（新 nonce）来消解——用户体验无感知。 同时 WorldServer 维护一个精确小列表（最近 N 秒内的 nonce 精确比对），双重保障。

11. Gate 迁移（Gate-Switch）处理

GateServer 断开（宕机、网络故障、运维重启）→ 客户端自动连接下一个 gateIP → 使用同一 SessionToken 重新登录。WorldServer 通过 15 秒迁移窗口实现无缝 session rebind。 

Gate_1 正常 → WorldServer：维持内部 TCP 连接，Session 绑定到 Gate_1
  │
Gate_1 断开（TCP FIN / timeout）
  │
WorldServer 收到 FIN：
  ├── 标记 SessionBinding.migration_deadline = now + 15s
  ├── 保留 session 状态（Entity、CryptoSession、缓冲区）
  └── 启动 15s 倒计时

客户端 → Gate_2：首包 MSG_LOGIN_ENTER_WORLD_REQ { SessionToken, nonce }
  │
Gate_2 → WorldServer：转发首包

WorldServer：
  ├── NonceVerifier.CheckAndInsert(nonce)
  ├── 验证 SessionToken（HMAC + 解密 + expireTime）
  ├── 查找 session → migration_deadline 有效？
  ├── YES → rebind Gate_2 的内部连接 → 清除 deadline → 玩家无缝在线
  └── NO  → 拒绝（需重新走 LoginServer）

15s 超时：
  → 保存玩家数据 → 销毁 Entity → 通知 CenterServer 清理位置索引
// WorldServer.cpp — Session 绑定 + Gate 迁移处理
struct SessionBinding {
    uint16_t currentGateId;
    uint64_t sessionId;
    SteadyClock::time_point migrationDeadline;  // zero = 正常

    bool IsMigrating() const {
        return migrationDeadline != SteadyClock::time_point{};
    }
};

void WorldServer::OnGateDisconnected(uint16_t gateId) {
    for (auto& [id, bind] : _sessionBindings) {
        if (bind.currentGateId == gateId && !bind.IsMigrating()) {
            bind.migrationDeadline = SteadyClock::now() + std::chrono::seconds(15);
            LOG_INFO("Session {} entered gate migration window", id);
        }
    }
}

void WorldServer::ProcessMigrationTimeouts() {
    auto now = SteadyClock::now();
    for (auto it = _sessionBindings.begin(); it != _sessionBindings.end(); ) {
        auto& bind = it->second;
        if (bind.IsMigrating() && now > bind.migrationDeadline) {
            CleanupSession(it->first);   // 保存 PG → 销毁 Entity → 通知 Center
            it = _sessionBindings.erase(it);
        } else ++it;
    }
}
迁移窗口折衷：15s 不是随意选的——TCP 超时通常 30s，但客户端 detect 断线 + 切换 gate 需要的时间远低于 30s。如果 Gate 宕机后被 monitor 自动重启，新的 Gate 实例需要 ~10s 才能就绪。 15s 是平衡"玩家不掉线"和"资源不浪费"的点。如果 15s 内没回来，玩家按离线处理（数据已保存）。
