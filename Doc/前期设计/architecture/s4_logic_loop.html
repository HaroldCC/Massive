4. 单线程逻辑层（WorldServer 内）

4.1 定位

LogicThread 只在 WorldServer 和 SocialServer 内存在。 GateServer/CenterServer 是纯 IO 进程，LoginServer 是同步处理进程，不需要异步逻辑循环。

⚠ 性能目标与压测策略： "单核 10000 PCU" 是基于 War Thunder 等项目的经验估算，但 War Thunder 是 vehicle combat （逻辑远轻于 MMO 的行为树 AI + NavMesh 寻路 + AOI 广播）。 当前设计采用单线程模型，但必须通过原型压测验证：

BenchmarkScene 测试： 创建 10000 个 entity（各带 Position/Velocity/Health/BuffList 等全套组件）， 模拟完整的 AOI + combat + buff + move + AI 管线，测量每 Tick 实际耗时。

关键变量： · AI 行为树评估（50μs/entity × 10000 NPC = 500ms 已是预算的 10x） · NavMesh FindPath（200μs/次 × 30% 移动中 = 60ms） · AOI 九宫格广播（实体密度决定）

如果实测超预算：升级为 Scene 级多线程——每个 Scene 一个独立 LogicThread （EnTT registry 天然 per-Scene 隔离）。此升级路径已在设计中预留。

4.2 核心循环：固定 20ms Tick + 防死亡螺旋 Clamp

void LogicServer::Run() {
    auto lastTime = std::chrono::steady_clock::now();
    constexpr auto tickInterval = std::chrono::milliseconds(20);
    constexpr auto maxElapsed   = std::chrono::milliseconds(50);

    while (!_stopped.load()) {
        ProcessMessages();                // Per-Session inbox DrainAll + MsgID 查表分发
        _timingWheel.Tick();                // 时间轮推进
        ProcessDBWorkerCallbacks();       // DBWorkerPool 完成的查询结果回调
        ProcessRpcResponses();            // Center/Social 的异步 RPC 回包

        auto now = std::chrono::steady_clock::now();
        auto elapsed = now - lastTime;

        if (elapsed > maxElapsed) elapsed = maxElapsed;
        lastTime = now;

        Tick(elapsed);                      // 游戏逻辑（DasLang 脚本）
        _logicContext.poll_one();
        FlushOutgoingMessages();          // 加密 → Gate 内部连接
        SendCenterHeartbeat();            // 向 CenterServer 报心跳

        if (elapsed < tickInterval)
            std::this_thread::sleep_for(tickInterval - elapsed);
    }
}

4.3 ProcessMessages：Per-Session inbox + 消息预算

IO 线程收包后解密→按 sessionId 找到对应 WorldSession→Enqueue 到其独立 inbox 队列（Per-Session MPSCQueue）。 LogicThread 每 Tick 遍历所有活跃 WorldSession 的 inbox，Drain 最多 kMaxMessagesPerTick 条消息。 

void LogicThread::ProcessMessages() {
    constexpr size_t kMaxPerTick = 1000;
    size_t processed = 0;

    for (auto& [sessionId, ws] : _sessions) {
        std::vector<LogicMessage> batch;
        ws.inbox.DrainAll(batch);
        for (auto& msg : batch) {
            if (processed >= kMaxPerTick) return;  // 预算耗尽，剩余积压
            _dispatcher.Dispatch(ws.entity, msg.msgID, msg.body);
            processed++;
        }
    }

    if (_pendingMessageCount > 5000)
        Log::Warn("LogicThread: incoming queue depth={}", _pendingMessageCount);
}

4.4 消息流完整时序（C2 拓扑）

步骤线程进程动作
1-2IO 线程GateServerTCP recv → 拆包 Length+MsgID+SessionId → 读 SessionId 查路由 → 写内部 TCP
3IO 线程WorldServer内部 TCP recv → 读 InternalHeader → 按 sessionId 查 _sessions（shared_mutex 读锁）→ ws.inbox.Enqueue（Per-Session MPSCQueue，无锁）
4-5逻辑线程WorldServer遍历 _sessions → ws.inbox.DrainAll → MsgID 数组索引 → Handler(body)。每 Tick 最多处理 kMaxPerTick 条消息
6逻辑线程WorldServer如需 DB：DBWorkerPool.AsyncQuery(sql, callback)——不阻塞 Tick
7-8逻辑线程WorldServerAES-GCM 加密 → InternalHeader → 写对应 Gate 的内部 TCP
9IO 线程GateServer内部 TCP recv → InternalHeader.sessionId → clientSocket → async_write

4.5 过载保护：降频 + 降级（不变）

同之前设计，3 状态机：Normal→Warning→Degraded。在所有 WorldServer 上各自独立运行。CenterServer 收集各 World 的过载状态做全局告警。

4.6.1 升级路径：Scene 级多线程

如果 BenchmarkScene 压测显示单线程无法满足目标 PCU，WorldServer 支持 Scene 级并行——每个 Scene 一个独立的 LogicThread。 

// WorldServer 升级为 Scene 级多线程
class WorldServer {
    struct SceneExecutor {
        std::thread logicThread;
        MpscQueue<LogicMessage> queue;  // 每个 Scene 独立队列
        Scene* scene;
    };
    std::vector<SceneExecutor> _sceneExecutors;
};

// IO 线程按 entity 的 sceneId 做消息分发
void DispatchToScene(const Message& msg) {
    auto sceneId = GetEntitySceneId(msg);
    _sceneExecutors[sceneId].queue.Enqueue(msg);
    // 可选：eventfd 唤醒对应 Scene 的 LogicThread
}
