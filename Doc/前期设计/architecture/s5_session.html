5. Session 生命周期管理

5.1 Gate Session vs World Session

C2 拓扑中有两层 Session：GateSession（连接级，Gate 持有）和 WorldSession（逻辑级，World 持有）。 一个客户端连接对应一个 GateSession + 一个 WorldSession。两者通过 sessionId 关联。

GateSessionWorldSession
持有方GateServerWorldServer
生命周期TCP 连接建立 → 断开Entity 创建 → Entity 销毁（可跨 TCP 重连保留）
状态sessionId, worldServerId, clientSocketsessionId, playerEntity, CryptoSession
断线行为通知 World → 销毁自身保留 Entity 30s 等待重连

5.2 完整生命周期

Client TCP → GateServer
  │
  ├── Gate: 分配 sessionId → 创建 GateSession
  │
  ├── Client → Gate: MSG_LOGIN_ENTER_WORLD_REQ {sessionId, sessionToken}
  │     Gate: 读 sessionToken[0..1] → worldServerId
  │     Gate: 建立/复用 到 WorldServer 的 TCP 连接
  │     Gate → World: InternalHeader + 原包
  │
  ├── World: HMAC 验证 SessionToken → 解密 → 提取 accountId + SessionKey
  │     World: 加载/创建 Entity → 绑定 WorldSession（sessionId → Entity）
  │     World: _sessions[sessionId] = WorldSession{...}
  │     World: 
  │     World → Gate → Client: MSG_LOGIN_ENTER_WORLD_RSP
  │
  ├── 正常运行
  │     Client ⇄ Gate ⇄ World
  │
  ├── TCP 断线（Gate 侧检测）
  │     Gate: GateSession 析构
  │     Gate → World: InternalHeader(MSG_DISCONNECT, sessionId)
  │     World: 给 Entity 加 DisconnectedTag + 注册 30s 超时定时器
  │     World: 保留 crypto 保留在 WorldSession 中
  │
  ├── 30s 内重连（客户端用同一个 SessionToken 连任意 Gate）
  │     Gate: 新 sessionId（新的 GateSession）
  │     Gate → World: MSG_LOGIN_ENTER_WORLD_REQ {新sessionId, 旧SessionToken}
  │     World: 从 SessionToken 还原 accountId → 找到原 Entity（DisconnectedTag 还在）
  │     World: _sessions[新sessionId] = WorldSession{...}（切换 sessionId 绑定）
  │     World: ecs_remove(DisconnectedTag) → 定时器空转跳过
  │
  └── 30s 超时
        World: 定时器触发 → Entity 仍带 DisconnectedTag → SaveDB → Destroy

5.3 WorldServer 侧关键数据

// WorldServer 内
struct WorldSession {
    uint32_t     sessionID;          // Gate 分配的 sessionId
    uint32_t     accountID;          // 玩家账号 ID
    Entity       entity;             // World 侧的玩家 Entity
    CryptoSession crypto;             // AES-256-GCM 加解密上下文
    uint16_t     gateServerID;       // 当前连接的 Gate 实例 ID
    MPSCQueue<LogicMessage> inbox;      // IO 线程 → LogicThread 每 Session 独立队列
    std::chrono::steady_clock::time_point lastRecvTime;
    bool         disconnected = false; // 是否处于断线等待状态
};

// 真理之源：只用一个 map
std::unordered_map<uint32_t, WorldSession> _sessions;        // sessionId → WorldSession
std::unordered_map<uint32_t, uint32_t>   _accountToSession;  // accountId → sessionId

void OnGateDisconnect(uint32_t sessionId) {
    auto it = _sessions.find(sessionId);
    if (it == _sessions.end()) return;

    auto& ws = it->second;
    ws.disconnected = true;
    ecs_emplace(ws.entity, type<DisconnectedTag>, DisconnectedTag{GetTickTime()});

    // 注册 30s 超时
    _timingWheel.Schedule(GenTimerId(), std::chrono::seconds(30), [this, sessionId] {
        auto it = _sessions.find(sessionId);
        if (it == _sessions.end()) return;
        if (it->second.disconnected) {
            SaveEntityToDb(it->second.entity);
            ecs_destroy(it->second.entity);
            _sessions.erase(it);
        }
    });

    // 保留 WorldSession 和 inbox 队列，不断清理
    // 如果 30s 内重连，从 SessionToken 找到旧 entity 重新绑定
}
