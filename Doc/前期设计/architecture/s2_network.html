2. 网络层 · IOContextPool 设计

2.1 核心思想

N 个独立 asio::io_context 各运行于独立线程，Round-Robin 分配连接，同一连接始终在同一线程（零锁竞争）。 所有 5 种进程都使用相同的 IOContextPool 组件——只是连接对象不同。

2.2 IOContextPool 实现

class IOContextPool {
public:
    IOContextPool(std::size_t size = std::thread::hardware_concurrency());
    asio::io_context& GetNextContext();
    void Stop();
private:
    std::vector<asio::io_context> _ioContexts;
    std::vector<WorkPtr> _works;
    std::vector<std::thread> _threads;
    std::atomic<std::size_t> _nextIndex{0};

2.3 各进程的连接拓扑

进程作为 Server 端接受作为 Client 端发起
LoginServer客户端 TLS 连接（短连接，登录即断）PgBouncer（查账号密码哈希、封禁状态）
GateServer客户端 TCP 连接（长连接，10K+）所有 WorldServer（内部 TCP 长连接，每 World 一条）
WorldServerGate/Center/Social 的内部 TCP 连接CenterServer（注册/心跳）、SocialServer（RPC）
CenterServerWorld/Social 的注册/心跳连接—（无 DB 访问）
SocialServerWorldServer 的 RPC 连接PgBouncer（公会/邮件/好友持久化）

注：DBWorkerPool 的 libpq 连接不走 asio——是独立的 Worker 线程，直接阻塞式 libpq 调用。结果通过 MPSC Queue 回到逻辑线程。

};

2.5 WorldServer 的 Session

WorldServer 不直接接受客户端 TCP。它接受来自 GateServer 的内部 TCP 连接。 每个 GateServer ↔ WorldServer 连接承载多个客户端的消息复用（通过 InternalHeader.sessionId 区分）。 

// WorldSession.h — WorldServer 侧的 session
class WorldSession {
public:
    uint32_t sessionId;
    Entity    playerEntity;
    CryptoSession crypto;           // AES-GCM 加密上下文

    void Send(std::vector<char> data) {
        _gateConn->Send(InternalHeader{sessionId}, crypto.Encrypt(data));
    }

private:
    std::shared_ptr<GateConnection> _gateConn;
};
