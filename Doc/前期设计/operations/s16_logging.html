16. 错误处理 · 日志 · 可观测性

16.1 日志格式与输出

使用 spdlog（C++20 header-only，工业级性能）。格式采用 printif 风格易读， 同时输出到终端（stdout）和日志文件。如果未开启终端（后台/守护进程），只写文件。 

// LogService.h — spdlog 配置
namespace Log {

inline void Init(const std::string& logDir, bool console) {
    auto fileSink = std::make_shared<spdlog::sinks::rotating_file_sink_mt>(
        logDir + "/massive.log", 10 * 1024 * 1024, 5);  // 10MB × 5 文件

    if (console) {
        auto consoleSink = std::make_shared<spdlog::sinks::stdout_color_sink_mt>();
        auto logger = std::make_shared<spdlog::logger>("massive",
            spdlog::sinks_init_list{consoleSink, fileSink});
        spdlog::register_logger(logger);
    } else {
        auto logger = std::make_shared<spdlog::logger>("massive", fileSink);
        spdlog::register_logger(logger);
    }
    spdlog::set_default_logger(spdlog::get("massive"));
    spdlog::set_pattern("[%Y-%m-%d %H:%M:%S.%e] [%^%l%$] [%n] [trace:%X] %v");
    spdlog::set_level(spdlog::level::info);
}

// 使用宏——开发中加性能埋点后可在 Tracy 中关联
#define LOG_ERROR(traceId, fmt, ...) spdlog::error("[{}] " fmt, traceId, ##__VA_ARGS__)
#define LOG_WARN(traceId, fmt, ...)  spdlog::warn("[{}] " fmt, traceId, ##__VA_ARGS__)
#define LOG_INFO(traceId, fmt, ...)  spdlog::info("[{}] " fmt, traceId, ##__VA_ARGS__)
#define LOG_DEBUG(traceId, fmt, ...) spdlog::debug("[{}] " fmt, traceId, ##__VA_ARGS__)

// C++ 侧
LOG_WARN(sessionId, "queue depth approaching limit: depth={} max={}", depth, kMaxQueueSize);
LOG_ERROR(trace, "db connection lost: {}", e.what());

// DasLang 侧桥接
LogInfo(msg: string)
LogWarn(msg: string)
LogError(msg: string)
级别绑定方法用途生产环境
ERRORLOG_ERROR(traceId, …)需立刻响应的故障：DB 断开、registry 损坏✅ 全量输出
WARNLOG_WARN(traceId, …)异常但可恢复：队列接近上限、认证失败、消息超时✅ 全量输出
INFOLOG_INFO(traceId, …)关键业务事件：登录/登出、等级提升、交易完成、场景切换✅ 全量输出
DEBUGLOG_DEBUG(traceId, …)开发调试：组件值变化、AOI 事件、each 循环次数❌ 可开关
TRACEspdlog::trace(…)极致细节：网络包内容 dump❌ 仅本机

16.3 性能指标与 Tracy 埋点

使用 Tracy（C++ 实时性能分析器）做开发期埋点。每个系统函数、DB 查询、Tick 阶段 用 ZoneScoped 标记——Tracy GUI 中可以按线程、按帧查看每段代码的耗时瀑布图。 生产环境通过编译宏禁用 Tracy（零开销）。 

#ifdef MASSIVE_ENABLE_TRACY
  #include <tracy/Tracy.hpp>
  #define MASSIVE_PROFILE()       ZoneScoped
  #define MASSIVE_PROFILE_NAME(x)  ZoneScopedN(x)
  #define MASSIVE_FRAME_MARK()     FrameMark
#else
  #define MASSIVE_PROFILE()
  #define MASSIVE_PROFILE_NAME(x)
  #define MASSIVE_FRAME_MARK()
#endif

// 使用——开发期 xmake f -m debug --tracy=y 即可
void LogicServer::Run() {
    while (!_stopped.load()) {
        MASSIVE_FRAME_MARK();  // 标记帧边界——Tracy 中按帧分析
        {
            MASSIVE_PROFILE_NAME("ProcessMessages");
            ProcessMessages();
        }
        {
            MASSIVE_PROFILE_NAME("TimingWheelTick");
            _timingWheel.Tick();
        }
        {
            MASSIVE_PROFILE_NAME("GameTick");
            Tick(elapsed);
        }
    }
}

// DB 查询埋点
void DbService::ExecuteQuery(const std::string& sql) {
    MASSIVE_PROFILE_NAME("DB_ExecuteQuery");
    // ... PG 查询
}

// 系统函数埋点——移动系统耗时一目了然
def SystemMovement(sceneId : uint32; dt : float) {
    // C++ 桥接函数内已埋 MASSIVE_PROFILE_NAME("SystemMovement")
    ecs_query(sceneId; pos : Position&; vel : Velocity) {
        pos.x += vel.vx * dt
    }
}
📌 Tracy 优势：零侵入（宏在 Release 下编译为空白）、帧级时间线、 跨线程追踪（DB 线程查询耗时也在同一 Timeline 上）、GPU 追踪、内存追踪、 无需外部数据库（Tracy GUI 直连应用端口）。

16.4 分布式请求追踪：双 traceId

traceId 由 GateServer 在拆包生成 LogicMessage 时生成（uint64_t 自增 + 时间戳编码）。 clientTraceId 由客户端可选传入（在 proto 消息体中）。如果客户端不传，留空。 

struct LogicMessage {
    uint32_t    sessionId;
    uint32_t    msgId;
    uint64_t    traceId;        // GateServer 生成，贯穿 Gate→World→DB
    uint64_t    clientTraceId;  // 客户端可选传入（0 表示未传）
    std::vector<char> body;
    std::chrono::steady_clock::time_point recvTime;
};

// GateServer 端 traceId 生成：时间戳高32位 + 自增序号低32位
static std::atomic<uint32_t> seq{0};
auto traceId = (uint64_t(time(nullptr)) << 32) | seq.fetch_add(1);

16.5 Crash 恢复

组件策略
WorldServer进程守护 (systemd Restart=always) 自动重启 → DB 加载场景快照 → 恢复在线玩家 Entity + 组件 → 通知 GateServer 更新路由
GateServer无状态，直接重启。客户端重连走其他 Gate。
DBServer主备切换。PgBouncer 自动路由到新 PG 实例。

16.6 Assert vs Panic

场景策略
C++ 引擎内部不变量MASSIVE_ASSERT 自定义断言宏：Debug 下 abort 进调试器，Release 下记录 ERROR 日志并继续执行（不 crash）。标准 assert() 在 Release 下被完全移除，无法满足需求。
DasLang 脚本逻辑错误panic → ERROR 日志 + 行号 → 返回错误给客户端，不 crash 服务器
DB 写入失败重试 3 次 → 每次间隔 100ms → 仍失败则 ERROR 日志 → 继续服务（不 crash）
内存耗尽主动 std::abort() + 生成 core dump，systemd 自动重启
EnTT registry 损坏panic → 记录全量 debug_dump → abort → 重启恢复

16.7 指标暴露与告警

应用层内嵌一个轻量 HTTP 服务器（Asio HTTP），暴露 /metrics 端点供 Prometheus 拉取。 告警规则由 Prometheus AlertManager 外部驱动，不内嵌在代码中。 

// MetricsEndpoint.h — 内嵌 /metrics HTTP 端点
class MetricsEndpoint {
public:
    MetricsEndpoint(asio::io_context& ctx, uint16_t port = 9090);

    // 指标注册（每个指标一个 gauge/counter）
    void RegisterGauge(const std::string& name, std::function<double()> getter);
    void IncrementCounter(const std::string& name);

    // 每 Tick 调用：更新所有指标值
    void Update();

private:
    asio::ip::tcp::acceptor _acceptor;
    std::unordered_map<std::string, GaugeMetric> _gauges;
    std::unordered_map<std::string, std::atomic<uint64_t>> _counters;
};

16.8 告警规则

告警规则由外部监控系统（Prometheus AlertManager）驱动，不在代码内嵌规则。 代码只负责暴露指标和输出日志。

指标告警条件级别
massive_errors_total{type="db_connection_fail"}> 0 for 1m🔴 紧急
massive_queue_depth> 80% 容量 for 3m🟡 警告
massive_tick_duration_ms> 45ms for 5m（接近 20ms Tick 上限）🟡 警告
massive_sessions_online突然下降 > 50% in 1m🔴 紧急
massive_db_query_duration_msp99 > 50ms for 5m🟡 警告
