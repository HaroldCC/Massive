10. 设计决策与权衡

10.1 IOContextPool vs 单 io_context + 多线程

维度IOContextPool单 io_context 多线程
锁竞争每个 io_context 独立队列单队列竞争
连接亲和性同连接始终同线程回调可能跨线程

10.2 为什么单线程逻辑

游戏逻辑是状态机，单线程保证确定性、无锁、可调试。万人同时在线单核足以支撑。

10.3 DasLang vs Lua

维度DasLangLua
性能AOT → 原生码，~C++解释/JIT，慢一个量级
类型强类型 + 编译检查动态类型
内存每 Context 独立 Heap，默认 Bump Allocator（无 GC 暂停）；可选 persistent_heap + Mark-Sweep GC全局 Mark-Sweep GC 有暂停
热更新函数级原生需 hack

10.4 命名规范

元素规范示例
类名/结构体名大驼峰LogicServer, Health
抽象类/接口大驼峰 + I 前缀IScene, IModule
命名空间大驼峰Mmo::Network
函数名大驼峰GetNextContext(), HandleMove()
类成员变量小驼峰 + _ 前缀_ioContexts, _sceneId
类静态常量大驼峰 + k 前缀kHotThreshold, kMaxPacketSize
结构体成员小驼峰（无前缀）current, sessionId
局部变量小驼峰entityId, totalLength
枚举值全大写 + 下划线MSG_MOVE_REQ
宏全大写 + 下划线REGISTER_COMPONENT

协议消息命名

方向后缀示例
客户端→服务器_ReqMSG_MOVE_REQ
服务器→客户端_RspMSG_MOVE_RSP
服务器主动推送_NtfMSG_ENTITY_CREATE_NTF
