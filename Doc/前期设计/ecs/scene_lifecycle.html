Scene 生命周期管理

1. 总览

Scene 是拥有独立 EnTT Registry + BlobStorage + AOI + NavMesh 的完整游戏世界单元。 按生命周期分为三类：

类型实例数创建时机销毁时机示例
常驻场景 预创建 3-10 个 WorldServer 启动时 WorldServer 关闭时 主城、野外、公共 PVP 区域
多实例副本（小型副本） N 个团队 × 1 个实例 团队队长进入时创建 所有成员退出后 5 分钟 5 人副本（死亡矿井、哀嚎洞穴）
单例副本（大型 raid） 1 个全局实例 第一个团队进入时创建 所有团队退出后 40 人 raid（熔火之心、黑翼之巢）
战场 匹配成功时创建 双方队伍匹配完成 战斗结束 10v10, 15v15

2. 常驻场景：预加载 + 预热

WorldServer 启动时根据配置文件预创建所有常驻场景。 预创建期间完成 NavMesh 加载 + AOI 网格初始化 + 模板 NPC 实体创建。 预创建完成后 server 才开始接受客户端连接。 

// GameWorld.h — 启动时预创建常驻场景
class GameWorld {
public:
    void Initialize(const ServerConfig& config) {
        for (auto& sceneCfg : config.scenes) {
            auto& scene = CreateScene(sceneCfg);
            // 预热：加载 NavMesh
            _navMeshManager.Load(scene.GetId(), sceneCfg.navmeshPath);
            // 预热：创建模板 NPC
            SpawnTemplateNPCs(scene);
            LOG_INFO(0, "Scene {} ({}) initialized", sceneCfg.id, sceneCfg.name);
        }
        _readyForConnections = true;
    }

private:
    std::unordered_map<uint32_t, std::unique_ptr<Scene>> _scenes;
    std::atomic<bool> _readyForConnections{false};
};

3. 多实例副本（5 人副本）

每个团队的副本拥有独立实例——不同团队的怪物独立、BOSS 独立、掉落独立。 实例在团队队长进入时创建，队伍全退后 5 分钟自动销毁。 

// DungeonManager.h — 多实例副本管理
class DungeonManager {
public:
    struct DungeonInstance {
        uint32_t dungeonId;       // 副本模板 ID（死亡矿井=1001）
        uint32_t instanceId;       // 实例 ID（全局唯一）
        uint32_t partyLeaderId;    // 团队队长 PlayerId
        uint32_t sceneId;          // 对应的 Scene ID
        std::set<uint32_t> partyMembers;
        std::chrono::steady_clock::time_point emptySince;  // 全退后开始倒计时
    };

    // 团队队长进入副本——创建实例
    uint32_t CreateInstance(uint32_t dungeonTemplateId, uint32_t partyLeaderId);

    // 查询玩家所在的副本实例
    std::optional<DungeonInstance> GetInstanceForPlayer(uint32_t playerId);

    // 玩家退出副本——更新成员列表
    void OnPlayerExit(uint32_t instanceId, uint32_t playerId);

    // 每 10 秒 Tick——检查是否有空实例需要销毁
    void CleanupEmptyInstances();

private:
    std::unordered_map<uint32_t, DungeonInstance> _instances;     // instanceId → 实例
    std::unordered_map<uint32_t, uint32_t> _playerToInstance;  // playerId → instanceId
    std::atomic<uint32_t> _nextInstanceId{1};

    static constexpr auto kEmptyDestroyDelay = std::chrono::minutes(5);
};

// 实例创建流程
uint32_t DungeonManager::CreateInstance(uint32_t dungeonId, uint32_t leaderId) {
    auto instanceId = _nextInstanceId.fetch_add(1);
    auto sceneId = instanceId + 100000;  // 副本实例的 sceneId 偏移

    auto& scene = GetGameWorld().CreateScene(SceneConfig{
        .id = sceneId,
        .name = "dungeon_{}_{}"_format(dungeonId, instanceId),
        .navmeshPath = "data/navmesh/dungeon_{}.navmesh"_format(dungeonId),
        .gridSize = 30.0,
        .viewRadiusXZ = 80.0,
        .viewRadiusY = 30.0
    });

    // 按副本模板创建 NPC/BOSS
    SpawnDungeonEntities(scene, dungeonId);

    _instances[instanceId] = {dungeonId, instanceId, leaderId, sceneId, {leaderId}, {}};
    _playerToInstance[leaderId] = instanceId;

    return instanceId;
}

4. 单例副本（40 人 Raid）

单例副本全局只有一个实例——所有团队共用同一个副本世界。 第一个团队进入时创建副本，所有团队退出后 10 分钟自动销毁。 BOSS 共享——不同团队在同一个副本中竞争或协作。 

struct RaidInstance {
    uint32_t raidId;
    uint32_t sceneId;
    std::set<uint32_t> activeTeams;   // 当前在副本中的所有团队 ID
    std::chrono::steady_clock::time_point emptySince;
};

class RaidManager {
    // 等同 DungeonManager 模式，但 key = raidTemplateId（非 instanceId）
    static constexpr auto kEmptyDestroyDelay = std::chrono::minutes(10);
    static constexpr uint32_t kMaxTeamsPerRaid = 8;  // 最多 8 个团队（320 人）
};

5. 战场

匹配系统将双方玩家放入一个新创建的 Scene。战斗结束后迁移所有存活玩家回原场景，销毁战场场景。 

struct BattlegroundInstance {
    uint32_t bgTemplateId;     // 战场模板 ID
    uint32_t sceneId;
    std::vector<uint32_t> teamA;   // 队伍 A 的 PlayerId 列表
    std::vector<uint32_t> teamB;
    uint32_t scoreA = 0, scoreB = 0;

    void EndBattle() {
        // 迁移所有存活玩家回原场景（走 §20.4 Clone迁移）
        for (auto playerId : teamA)
            MigrateEntityToScene(playerId, GetHomeSceneId(playerId));
        for (auto playerId : teamB)
            MigrateEntityToScene(playerId, GetHomeSceneId(playerId));
        GetGameWorld().DestroyScene(sceneId);
    }
};

7. 场景销毁流程

Scene 标记为待销毁
  │
  ├── 1. 停止接受新实体（拒绝 ecs_create）
  │
  ├── 2. 迁移剩余玩家（如战场结束 / 副本关闭）
  │     所有玩家 MigrationToScene 回主城
  │
  ├── 3. 检查所有实体已迁出（entity count == 0）
  │
  ├── 4. ~~Unload NavMesh~~
  │
  ├── 5. Scene 析构 → EnTT registry 销毁 + BlobStorage 释放
  │
  └── 6. 从 GameWorld._scenes 中移除
