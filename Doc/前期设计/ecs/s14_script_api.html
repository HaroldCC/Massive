✔ 已确认

14.1 ECS API — 6 核心原语

两个模式覆盖所有操作。无 type<T> 传递——类型从注解和闭包参数自动推导。 无 get/copy/set 三步曲——ecs_edit 闭包内直接 cmp.field 赋值，底层是 C++ 引用。

API模式签名说明
ecs_query 批量遍历 ecs_query(sceneId; f1:T1&; f2:T2; with...; without...) { ... } 声明式多组件迭代，变量是引用，零拷贝。with/without 过滤。
ecs_edit 单实体操作 ecs_edit(entity) $(cmp) { cmp.health.current -= 10 } ComponentMap 闭包，cmp.field.subfield 直接读写。自动路由 EnTT / BlobStorage。
ecs_create 生命周期 (sceneId:uint32): Entity 创建实体（延迟生效，commit 时可见）
ecs_destroy 生命周期 (we:Entity) 销毁实体（延迟生效，commit 时清理）
ecs_remove 组件操作 ecs_remove(entity, type<T>) 从实体移除指定组件
ecs_stage 调度 ecs_stage "name" { ... } 声明执行阶段，前后自动 commit。组织所有系统执行顺序。

14.2 模式 1：ecs_query — 批量遍历（替代 ecs_view + 手动 zip）

// system_movement.das — 移动系统（C++ EnTT 组件）
[export]
def SystemMovement(sceneId : uint32; dt : float)
{
    // ⭐ 声明式：一个 query 替代 let + let + for zip
    ecs_query(sceneId;
        pos : Position&;   // & = 可变引用，赋值直接改 EnTT storage
        vel : Velocity;
        with MonsterTag;    // 过滤：只遍历有 MonsterTag 的实体
        without Stunned     // 过滤：排除晕眩中的实体
    ) {
        pos.x += vel.vx * dt
        pos.y += vel.vy * dt
        pos.z += vel.vz * dt
    }
}

// combat_system.das — 战斗系统
[export]
def SystemCombatDamageTick(sceneId : uint32)
{
    ecs_query(sceneId;
        hp : Health&;
        dmg : DamageOverTime;
        with CombatTag
    ) {
        hp.current -= dmg.damagePerTick
        if (hp.current <= 0) {
            hp.current = 0
            ecs_dispatch("on_entity_death", hp)  // 延迟处理死亡
        }
    }
}

// 脚本组件也支持 ecs_query — BlobStorage 遍历同样高效
def SystemBuffTick(sceneId : uint32)
{
    ecs_query(sceneId;
        buf : BuffState&;
        without Paused
    ) {
        buf.remainingTicks -= 1
        if (buf.remainingTicks <= 0) {
            ecs_remove_component(buf, type<BuffState>)
        }
    }
}
对比老方案：不再需要 let arr1 = ecs_view(id, type<A>) → let arr2 = ecs_view(id, type<B>) → for a, b in arr1, arr2。 新方案一行 ecs_query 声明所有需要的组件 + 过滤条件，编译期展开为 EnTT owning group，保证类型对齐。

ecs_query 性能说明

owning group 在 entity 创建/销毁时做物理重排（O(owned 组件数)），但创建/销毁频率远低于遍历频率。 对移动系统（每 Tick 1000 个 entity，新增/移除 5 个），重排开销 ≈ 每帧 5 × (O(2) + O(2))，微不足道。 遍历热路径零额外开销——直接走 aligned raw pointer。

⚠ ecs_query 内不可做结构性修改：在 ecs_query 的 block 内调用 ecs_destroy() 或 ecs_emplace() 会使 owning group 的内部 entity 列表失效（类似在 C++ 的 for-each 中修改容器）。 如需在遍历中删除实体，请将 entity 加入 pending 队列，在 Stage 末尾统一处理。

14.3 模式 2：ecs_edit — 单实体操作（替代 ecs_get/ecs_set/ecs_emplace）

// ⭐ ComponentMap 闭包模式——零拷贝、零 type<T> 参数
def ApplyDamage(target : Entity; damage : int)
{
    ecs_edit(target) $(var cmp)
    {
        // cmp.health 是 Health&，直接写 EnTT storage
        // cmp.buffState 是 BuffState*，直接写 BlobStorage
        // ——对脚本开发者透明
        cmp.health.current -= damage

        if (cmp.health.current <= 0) {
            cmp.health.current = 0
            ecs_destroy(target)
        }
    }
}

def SpawnMonster(sceneId : uint32; x : float; y : float) : Entity
{
    let e = ecs_create(sceneId)
    ecs_edit(e) $(var cmp)
    {
        cmp.position = Position{x = x, y = y, z = 0.0}
        cmp.health   = Health{current = 100, max = 100}
        cmp.velocity = Velocity{vx = 0.0, vy = 0.0, vz = 0.0}
    }
    return e
}

// Quest 系统 — 脚本组件同样用 ecs_edit
[script_component]
struct QuestProgress {
    questId  : int
    step     : int
    progress : int
}

def StartQuest(player : Entity; questId : int)
{
    ecs_edit(player) $(var cmp)
    {
        cmp.questProgress = QuestProgress{questId = questId, step = 1, progress = 0}
    }
}

def UpdateQuestProgress(player : Entity; delta : int)
{
    ecs_edit(player) $(var cmp)
    {
        cmp.questProgress.progress += delta
        if (cmp.questProgress.progress >= 100) {
            cmp.questProgress.step += 1
            cmp.questProgress.progress = 0
        }
    }
}
对比老方案：不再需要 let hp = ecs_get(target, type<Health>) → 改拷贝 → ecs_set(target, type<Health>, hp) 三行。 新方案 cmp.health.current -= 10 一行完成，底层是 EnTT 引用，零拷贝。

14.4 ecs_stage — Stage 组织系统执行

每 Tick 的调度用 ecs_stage 声明，每个 Stage 前后自动 commit()。 执行顺序由声明顺序决定，清晰地反映了数据依赖关系。 

// server_tick.das — 完整 Tick 调度
[export]
def ServerTick(sceneId : uint32; dt : float)
{
    // 1. 输入处理：消息队列 → Entity 操作（可能创建/销毁实体）
    ecs_stage "input"    { ProcessMessages(sceneId) }

    // 2. 属性重算：装备/Buff 变更后的 Stats 刷新
    ecs_stage "stats"    { SystemRecalcStats(sceneId) }

    // 3. 移动：ecs_query 批量更新 Position
    ecs_stage "movement" { SystemMovement(sceneId, dt) }

    // 4. 战斗结算：伤害公式、死亡判定
    ecs_stage "combat"   { SystemCombat(sceneId) }

    // 4. Buff/状态：计时器推进
    ecs_stage "buff"     { SystemBuffTick(sceneId, dt) }

    // 5. AI 决策：行为树/状态机
    ecs_stage "ai"       { SystemAI(sceneId) }

    // 6. 业务系统：任务、技能 CD、交易
    ecs_stage "quest"    { SystemQuest(sceneId) }
    ecs_stage "skill"    { SystemSkillCooldown(sceneId) }

    // 7. AOI：空间索引更新 → 计算 visible sets
    ecs_stage "aoi"      { SystemAOI(sceneId) }

    // 8. 网络复制：Ghost 创建/销毁/脏数据序列化
    ecs_stage "replicate"{ SystemReplicate(sceneId) }

    // 9. 持久化：脏数据批量写 DB
    ecs_stage "save"     { SystemDirtyFlush(sceneId) }
}

commit 机制保证数据一致性

操作Stage 内效果commit() 后（Stage 边界自动调用）
ecs_create()分配 ID，入创建队列实体在后续 Stage 的 ecs_query 中可见
ecs_destroy()标记待删，入销毁队列实体从所有 View/Storage 中移除
cmp.xxx = val（ecs_edit 内）立即写入引用（即时生效）脏标记自动置位
ecs_dispatch("event")事件入队列事件在 commit 时发送（同一 Tick 内）

14.7 热更新

DasLang 原生支持 Context::restart() + relocateCode() 函数级热更新。 所有游戏状态在 C++ EnTT + BlobStorage 中，脚本不持有状态。

更新内容操作状态影响
System 函数实现保存 .das → 重新编译 → 新函数指针替换同函数签名：无影响。改参数：需手动迁移。
C++ Component 定义改 Components.h → 重启服务器所有实体丢失——需 DB 迁移脚本
脚本 Component 定义 改 struct → 热重载 ecs_reload_schema() 旧字段保留、新字段填默认值。version 字段做兼容判断。
ecs_stage 调度顺序改 ServerTick 函数 → 热重载即刻生效，无数据影响
事件监听器改 ecs_listen 注册 → 热重载旧监听器注销，新监听器注册
