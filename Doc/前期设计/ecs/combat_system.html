战斗系统基础设施 · 伤害管线 + 属性系统

1. 设计哲学

战斗系统是 MMO 服务器的核心热路径。设计约束： 每 Tick 数千次伤害计算不能成为瓶颈。 伤害管线采用 固定阶段流水线（非插件式钩子），每个阶段是简单的数学变换， 没有虚函数调用、没有动态内存分配。所有伤害公式参数从 ConfigTable 查表， 公式本身在 DasLang 脚本中定义（可热更新）。

2. 属性系统

2.1 属性定义（C++ 侧，高频→EnTT）

// Components.h — 战斗属性组件（高频，存 EnTT）

// 基础属性——装备/等级/加点直接修改
struct Attributes {
    int32_t  strength      = 0;   // 力量 → 物理攻击
    int32_t  agility       = 0;   // 敏捷 → 暴击率、闪避
    int32_t  intelligence  = 0;   // 智力 → 魔法攻击
    int32_t  stamina       = 0;   // 耐力 → 最大 HP
    int32_t  spirit        = 0;   // 精神 → 回复速度
};

// 战斗属性——每 Tick 频繁读写
struct BattleStats {
    int32_t  maxHp         = 0;
    int32_t  currentHp     = 0;
    int32_t  maxMp         = 0;
    int32_t  currentMp     = 0;
    int32_t  attack        = 0;   // 最终攻击力
    int32_t  defense       = 0;   // 最终防御力
    int32_t  magicAttack   = 0;
    int32_t  magicDefense  = 0;
    int32_t  critRate      = 0;   // 暴击率（万分比：500 = 5%）
    int32_t  critDamage    = 0;   // 暴击伤害加成（万分比：1500 = +15%）
    int32_t  dodgeRate     = 0;   // 闪避率（万分比）
    int32_t  hitRate       = 0;   // 命中率（万分比）
    int32_t  attackSpeed   = 0;   // 攻击速度（万分比，10000 = 1.0）
    int32_t  moveSpeed     = 0;   // 移动速度（万分比）
};

2.2 属性重算触发

Attributes 变化（换装备、升级、加点）→ 标记 StatsDirtyTag → 下一 Tick 的 ecs_stage "stats" 中全量重算 BattleStats。 重算公式：基础属性 × 装备系数 + Buff 加成。结果直接写回 BattleStats 组件。 

// 属性重算系统——DasLang 侧，可热更新公式
[export]
def SystemRecalcStats(sceneId : uint32)
{
    ecs_query(sceneId;
        attr : Attributes&;
        stats : BattleStats&;
        equip : EquipmentSlots;          // 脚本组件
        with StatsDirtyTag
    ) {
        // 1. 基础值 = 属性 × 系数（ConfigTable）
        let cfg = g_classConfig.Find(GetPlayerClass(attr))
        stats.attack  = attr.strength * cfg.strToAtk / 100
        stats.defense = attr.agility * cfg.agiToDef / 100
        stats.maxHp   = attr.stamina * cfg.staToHp
        stats.maxMp   = attr.intelligence * cfg.intToMp

        // 2. 装备加成
        for slotId = 0; slotId < EquipmentSlots::MAX_SLOTS; slotId++ {
            let equipped = equip.slots[slotId]
            if (equipped == null) continue
            let itemCfg = g_itemTemplates.Find(equipped.itemId)
            if (itemCfg != null) {
                stats.attack  += itemCfg.attackBonus
                stats.defense += itemCfg.defenseBonus
                stats.maxHp   += itemCfg.hpBonus
                stats.critRate += itemCfg.critBonus
            }
        }

        // 3. Buff 加成（由 BuffSystem 处理，此处只做基准）
        stats.currentHp = min(stats.currentHp, stats.maxHp)
        stats.currentMp = min(stats.currentMp, stats.maxMp)

        // 4. 清除脏标记
        ecs_remove_component(attr, type<StatsDirtyTag>)
    }
}

3. 伤害管线（Damage Pipeline）

3.1 管线阶段

伤害计算分为 6 个固定阶段。每个阶段是纯函数，输入→输出， 无副作用、无虚函数。顺序固定，不允许跳过阶段。 

DamageEvent{attacker, defender, skillId, baseDamage, damageType}
  │
  ├── 阶段 1: 命中判定
  │     hitRate = attacker.hitRate - defender.dodgeRate
  │     isHit = Random(0, 10000) < hitRate
  │     isHit == false → 返回 MissResult → 管线结束
  │
  ├── 阶段 2: 暴击判定（PRD 伪随机）
  │     // 使用 Dota 2 / LoL 标准的伪随机分布 (PRD)
  │     // 每次不暴击，暴击概率递增；暴击后重置
  │     // 避免纯随机的连续暴击/连续不暴击，提升玩家体验
  │     isCrit = RollCritPRD(attacker.critRate, defender.critState)
  │     critMultiplier = isCrit ? (1.0 + attacker.critDamage / 10000.0) : 1.0
  │
  ├── 阶段 3: 基础伤害计算
  │     rawDamage = baseDamage × critMultiplier
  │     if (damageType == PHYSICAL)
  │         rawDamage = rawDamage × (1.0 - defense / (defense + K))  // 护甲减伤曲线
  │     if (damageType == MAGICAL)
  │         rawDamage = rawDamage × (1.0 - magicDefense / (magicDefense + K))
  │
  ├── 阶段 4: 伤害修正（Buff/被动技能）
  │     damage = rawDamage × Π(increaseFactors) × Π(reduceFactors)
  │     increaseFactors: 增伤 Buff、易伤 Debuff、种族克制
  │     reduceFactors:   减伤 Buff、护盾、无敌
  │     每个 factor 从 BuffList 组件中收集
  │
  ├── 阶段 5: 吸收/护盾
  │     absorbed = min(damage, shieldRemaining)
  │     damage -= absorbed
  │     shieldRemaining -= absorbed
  │
  └── 阶段 6: 应用伤害 + 事件
        defender.currentHp -= damage
        投递 ecs_dispatch("on_damage_dealt", DamageResult)
        投递 ecs_dispatch("on_damage_received", DamageResult)
        if (defender.currentHp <= 0)
            投递 ecs_dispatch("on_entity_killed", KillEvent)

3.2 管线实现（C++ 侧——热路径，零分配）

// DamagePipeline.h — 伤害管线（C++ 引擎层，最高性能）

struct DamageEvent {
    Entity attacker;
    Entity defender;
    uint32_t skillId;
    int32_t  baseDamage;
    enum class Type { Physical, Magical, True } damageType;
};

struct DamageResult {
    bool    isHit;
    bool    isCrit;
    int32_t finalDamage;
    int32_t absorbedByShield;
    int32_t hpBefore;
    int32_t hpAfter;
    enum class Outcome { Miss, Hit, Crit, Kill } outcome;
};

class DamagePipeline {
public:
    // execute 是纯静态方法——无状态，可在 DasLang 直接调用
    static DamageResult Execute(const DamageEvent& event,
                              const BattleStats& atkStats,
                              const BattleStats& defStats,
                              const BuffList* defBuffs);    // 脚本组件，可为 nullptr

private:
    static bool    CheckHit(const BattleStats& atk, const BattleStats& def);
    static bool    CheckCrit(const BattleStats& atk);
    static int32_t CalcRawDamage(int32_t base, bool crit, const BattleStats& atk, const BattleStats& def, DamageEvent::Type type);
    static int32_t ApplyModifiers(int32_t raw, const BuffList* buffs, DamageEvent::Type type);
    static int32_t ApplyShield(int32_t damage, const BuffList* buffs);

    static constexpr int32_t kDefenseConstant = 5000;  // 护甲减伤曲线常数 K
};

3.3 伪随机分布 (PRD) 算法

暴击和闪避使用 Dota 2 / League of Legends 标准的伪随机分布（Pseudo-Random Distribution）。 纯随机 rand() < critRate 虽然期望正确，但可能导致玩家连续 5 次暴击或不暴击——体验极差。 PRD 保证暴击均匀分布，长期期望 = 标称值。 

// PRDSystem.h — 伪随机分布（BlobStorage per-entity 状态）
[script_component]
struct PRDState {
    float critChance;   // 当前实际暴击概率（从 C 值开始，逐渐递增）
    float dodgeChance;  // 当前实际闪避概率
}

// 标称暴击率 → PRD C 值查表（Dota 2 标准）
// C 值 = 初始暴击概率，每次不暴击递增 C，暴击后重置为 C
static float NominalToPRDC(float nominal) {
    // 精确值见 Dota 2 Gamepedia PRD 表，此处用近似公式
    if (nominal <= 0.01f) return 0.00014f;   // ~1%
    if (nominal >= 0.80f) return 0.6f;        // ~80%
    return nominal * 0.32f;                      // 近似 C ≈ nominal × 0.32
}

bool RollCritPRD(BattleStats& atk, PRDState& state) {
    float roll = Random01();
    if (roll < state.critChance) {
        state.critChance = NominalToPRDC(atk.critRate / 10000.0f);  // 暴击——重置
        return true;
    }
    state.critChance += NominalToPRDC(atk.critRate / 10000.0f);   // 不暴击——递增
    return false;
}

// 闪避同理——使用独立的 dodgeChance 状态
bool RollDodgePRD(BattleStats& def, PRDState& state) {
    float roll = Random01();
    if (roll < state.dodgeChance) {
        state.dodgeChance = NominalToPRDC(def.dodgeRate / 10000.0f);
        return true;
    }
    state.dodgeChance += NominalToPRDC(def.dodgeRate / 10000.0f);
    return false;
}
适用范围：PRD 仅用于暴击和闪避——这两个对玩家战斗体验影响最大。 其他概率系统（格挡、掉落、命中）保持纯随机以减少 per-entity 状态开销。 PRDState 存为 BlobStorage 脚本组件，每 entity 额外开销仅 2 个 float = 8 字节。

3.4 DasLang 侧调用

// combat_handler.das — 技能伤害结算
def HandleSkillDamage(attacker : Entity; defender : Entity; skillId : uint32; baseDamage : int)
{
    ecs_edit(attacker) $(var atkCmp) {
    ecs_edit(defender) $(var defCmp)
    {
        let event = DamageEvent{
            attacker   = attacker,
            defender   = defender,
            skillId    = skillId,
            baseDamage = baseDamage,
            damageType = GetSkillDamageType(skillId)
        }

        // 调用 C++ 管线
        let result = ExecuteDamagePipeline(event, atkCmp.battleStats, defCmp.battleStats, &defCmp.buffList)

        // 应用结果
        if (result.outcome == DamageOutcome::Miss) {
            SendToClient(attacker, MSG_COMBAT_FLOAT_NTF, BuildFloatMsg(defender, "MISS"))
            return
        }

        defCmp.battleStats.currentHp = result.hpAfter

        // 广播伤害数字
        let floatType = result.isCrit ? "CRIT" : "DMG"
        BroadcastNearby(defender, MSG_COMBAT_FLOAT_NTF,
            BuildFloatMsg(defender, floatType, result.finalDamage))

        // 事件投递
        if (result.outcome == DamageOutcome::Kill) {
            ecs_dispatch("on_entity_killed", attacker, defender, skillId)
        }
    }}
}

6. 仇恨系统（Threat）

仇恨表是每个怪物 Entity 的脚本组件（BlobStorage），记录所有攻击者的威胁值。 

// 脚本组件——ThreatTable（低频，BlobStorage）
[script_component]
struct ThreatEntry {
    targetEntity : Entity
    threat       : int64_t       // 累积威胁值
}

[script_component]
struct ThreatTable {
    entries     : array<ThreatEntry>   // 按 threat 降序排列
    dirty       : bool                 // 需要重排序
}

// 威胁更新
def AddThreat(monster : Entity; attacker : Entity; amount : int64_t)
{
    ecs_edit(monster) $(var cmp)
    {
        let found = false
        for var entry in cmp.threatTable.entries {
            if (entry.targetEntity == attacker) {
                entry.threat += amount
                found = true
                break
            }
        }
        if (!found) {
            cmp.threatTable.entries |> push(ThreatEntry{targetEntity = attacker, threat = amount})
        }
        cmp.threatTable.dirty = true
    }
}

// 获取仇恨目标——最高威胁值
def GetTopThreatTarget(monster : Entity) : Entity
{
    var result = InvalidEntity
    ecs_edit(monster) $(var cmp)
    {
        if (cmp.threatTable.dirty) {
            // 按 threat 降序排序
            cmp.threatTable.entries |> sort($(a, b) => b.threat < a.threat)
            cmp.threatTable.dirty = false
        }
        if (!cmp.threatTable.entries |> empty()) {
            result = cmp.threatTable.entries[0].targetEntity
        }
    }
    return result
}

6.1 威胁值计算规则

行为威胁值
造成 1 点伤害+1 威胁
治疗（过量治疗无效）+0.5 威胁/每点治疗
嘲讽技能威胁值 = 当前最高威胁 × 1.1（强制成为第一目标）
进入战斗初始+10 威胁（先手仇恨）
超出怪物追击范围威胁清零（脱战）

6.2 目标切换逻辑（DasLang 侧）

// 怪物 AI 决策——目标选择
def MonsterSelectTarget(monster : Entity) : Entity
{
    let topTarget = GetTopThreatTarget(monster)
    if (topTarget == InvalidEntity) {
        return InvalidEntity
    }

    // 检查目标是否在追击范围内
    let dist = DistanceBetween(monster, topTarget)
    if (dist > GetMonsterChaseRange(monster)) {
        ClearThreatTable(monster)      // 脱战——清零仇恨
        ecs_dispatch("on_monster_evade", monster)
        return InvalidEntity
    }

    return topTarget
}

8. 性能分析

操作频率单次耗时每 Tick 总耗时
属性重算仅在换装/升级时触发（低频）~5μs可忽略
伤害管线100 个怪物 × 每 2s 一次 = 50/sec~2μs（纯数学）~0.1ms
仇恨排序同上（仅 dirty 时）~10μs（5 条目）~0.5ms
战斗状态检查100 实体 × 每 Tick~0.1μs~0.01ms
📌 结论：战斗管线每 Tick 总开销 < 1ms，远低于 50ms Tick 预算。伤害管线走 C++ 纯数学路径，零堆分配， 最高频的操作（命中判定、暴击判定、护甲减伤）都在静态函数内完成。

10. 死亡与复活流程

Entity.currentHp ≤ 0
  │
  ├── 1. 添加 DeadTag
  │     ecs_emplace(entity, DeadTag{deathTime = GetTickTime()})
  │
  ├── 2. 清除 Buff/Debuff（可配置哪些 Buff 死亡不消失）
  │     RemoveExpirableBuffs(entity)
  │
  ├── 3. 清除仇恨表
  │     ClearThreatTable(entity)
  │
  ├── 4. 投递事件
  │     ecs_dispatch("on_entity_killed", killer, victim, skillId)
  │     → 经验结算、掉落生成、任务进度更新、成就触发
  │
  ├── 5. 死亡状态持续
  │     玩家：显示释放尸体 UI，可选原地复活（消耗道具）or 墓地复活
  │     怪物：N 秒后尸体消失 → ecs_destroy
  │
  └── 6. 复活
        玩家：ecs_remove(DeadTag) → 恢复 HP/MP → 传送回复活点
        副本/战场内：特殊复活规则（次数限制、复活等待时间）
